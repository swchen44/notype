# notype 三場景提示詞設計

日期：2026-10-25。來源為使用者提供的口述、翻譯及「隨便問」草稿與後續明確回答；正式規格及驗收見 [#8](https://github.com/swchen44/notype/issues/8)，實作切片見 [#17](https://github.com/swchen44/notype/issues/17)。此文件不代表真實模型品質已驗收，也不宣稱已驗證 Typeless 的內部實作。

## 已確認共同規則

- 場景為口述、翻譯、隨便問，三份提示詞獨立編輯、保存及還原。使用者已明確選擇「只需要還原預設提示詞」，不新增整體設定重設。
- 開始鍵預設依序 Right Alt、Right Alt + Right Shift、Right Alt + Space。點按開始，錄音中以獨立可設定的停止鍵結束，預設 Right Alt；Esc 取消。共享前綴一次只產生一個動作。
- 開始當次錄音時保存場景、提示詞、辨識模式及翻譯目標等設定快照，設定修改不改變處理中的 request。明確重試依該筆歷史的場景／目標語言，以重試當下該場景提示詞建立新快照。
- 使用者設定的場景提示詞是可信設定；原稿與術語表是結構化資料，使用不同信任層級。自訂內容必須實際生效，不能被隱藏的預設文風或 few-shot 蓋過。
- 文字結果只作顯示、保存與受保護交付，不執行工具或自動送 Enter。各場景失敗／timeout／取消均沿用原稿保存與待選規則。

## 口述預設

採角色、處理原則、格式、限制及公開 few-shot。忠實整理贅詞、標點及明確自我修正，保留語意、語氣、數字、否定、條件、英文與 code；保留已有不確定資訊，不自行補上聽不到的內容或講者。中文排版保護 code、URL、路徑、email、小數及版本號。具體草稿已納入 #8／#11，#17 提供可編輯及還原的版本。

## 翻譯預設

採使用者提供的四要素：

1. 角色：具目標語言語境能力的專業翻譯員。
2. 任務：翻譯當次原稿，保留原意、語氣、專業術語及有意義的格式。
3. 約束：自然、符合語境的意譯，仍保留數字、否定、條件、單位及不確定資訊；不可用流暢度作為新增／刪減事實的理由。code、識別字、URL、路徑及精確字面值按原樣保留。
4. 輸出：純文字譯文，按目標語言使用標點及排版；不附語言偵測結果、說明、分析或 JSON 包裝。API transport 的 JSON 不等於要插入文字框的內容格式。

目標語言、可選領域與語氣為本機設定。預設目標依圖片採英語（美國），語氣預設保留原文，未指定領域時只依當次文字處理，不推測使用者職業／公司背景。來源語言及中英混合內容由同一次翻譯 request 理解，避免為偵測來源再發一個請求。

手動術語對照表提供原文→譯文資料，依目標語言區分；只有當次文字確實包含／語境清楚對應的詞才使用，不憑空加入未說出的名詞。一般術語表及對照表都不當成指令。動態模板的可信設定與原稿／詞彙資料分開編碼，不以可插入指令的字串拼接。

以目標語言的語法、標點與排版指示處理中／日／韓與英／法／德等差異。未取得實際模型介面前，不設計沒有 backend 意義的「語言權重」數字控制，也不保證任意公司模型都具備同等多語品質。

## 隨便問預設

使用者已確認「依口述意圖，回答問題或代寫內容」。方向是意圖導向、低摩擦、本機歷史及結構化思考：回答問題，或辨識口述中的目標、範圍、排除條件及步驟，將無序想法產出為可使用的文字；例如將「下週會議改到週三下午兩點，不用準備簡報」代寫為清楚的通知。只在有助完成任務時分段／列點，不強迫所有短答使用標題，也不編造未提供的姓名、日期或事件。

使用者後續縮減範圍，**本期不取得網站網域、不做逐網站整合**。情境只保留通用的 App 名稱，無法取得時採一般文風；不讀取視窗標題、頁面、輸入文字或網址來猜測。外部 metadata 是資料，不能成為指令來源；在開始當次 session 時取得快照。這不影響使用者手動填寫的翻譯「領域」。

## 可選回譯

使用者已確認是否回譯由使用者選擇。啟用時將譯文譯回來源語言，與原稿／譯文一同提供核對；不能以回譯或相同模型的自我一致性保證語意正確。回譯失敗時也需保存已產生的譯文及明確狀態，不能將其丟棄或冒充驗證通過。

使用者已確認回譯**預設關閉**；開啟後先顯示譯文與回譯，**明確確認後才嘗試交付**。確認仍受原輸入目標與去重條件保護，不能因已核對而貼到任意目前視窗。確認須對應使用者實際看過的結果版本；重試或結果變更會使舊確認失效。回譯進行前先保存主要譯文，第二階段失敗、取消或重啟仍可找回譯文與原稿。

來源草稿中的「零數據保留／不訓練」不能由客戶端代替公司伺服器作保證。本機歷史依既定需求保留到手動刪除；公司端政策與實際處理另列 #15 驗收，不以 OpenAI 相容的通訊格式當作資料政策證明。

## 驗證方式

Public session／HTTP／真實 SQLite／Tauri commands 與可見 UI 驗證路由、設定快照、保存、還原隔離、錯誤／取消及 migration。合成 fixture 可證明 request 與流程，不代替真實模型的翻譯或意圖品質。

翻譯評測包含數字、否定、條件、技術術語對照、金融／地理等歧義詞、混合語言、code／URL／小數及目標語言標點，與獨立參考譯文比較。若使用回譯，將它當成輔助語意檢查，不能以相同模型的自我一致性或字串相似就宣布品質通過。真實公司測試待可用環境與本機憑證就緒後執行。
