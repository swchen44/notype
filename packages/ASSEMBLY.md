# Portable package contracts and assembly plan

All three source package templates remain **private and unassembled**; placeholders refuse before activation/launch. A separate actual private local pilot has now passed Release build, three full tarball audits, offline installation, two local CPU recognition modes, hidden Fixed WebView2 startup and bounded facade-update/history preservation. See the [artifact receipt](../docs/verification/portable-local-assembly.md) and [prepared local trial](../docs/local-trial.md). Full clean-machine/native-update/public-deployment acceptance remains open. Do not publish source placeholders or treat a small facade tarball as the complete local app.

## Roles and trust

`notype/` is the small facade. `notype-win32-x64/` is an application-specific Windows payload containing notype and the **whole** fixed Microsoft runtime, not a standalone runtime offering. `notype-model/` represents an independently pinned functional speech-model dependency. Names are provisional; no publisher scope/name reservation is implied. The root private Node package remains a diagnostic prototype and is not packed into the product.

Final facade `release.json` schema 2 must have `status: "assembled"`, a version matching its package.json, and an exact `application` pin: `{name, version, manifest: "payload.json", sha256}`. The facade depends only on the App and has no model dependency or optional dependency. An optional `model` pin describes an independently supplied model package; normal startup can reach model-folder recovery when it is absent or invalid. `--check` strictly checks every declared model pin. Pin exact versions; do not use tags/ranges. These dependencies remain absent from the unassembled source template.

Each payload.json declares schema/name/version/role, a nonempty exact file list, and provenance sources. Each file has `{path, role, bytes, sha256, source}`; paths use `/`. `sources[source]` contains a public HTTPS `source` URL without credentials/query/fragment, immutable `revision`, actual `license` identification and `notices` paths. Every notice must itself be a declared, hashed notice file. Preserve proprietary component terms; an observed artifact SHA is not a publisher-provided digest or a redistribution grant.

Application metadata declares `platform: "win32"`, `arch: "x64"`, `cpu`, `entrypoint`, `hostProbe`, `hostProbeLibraries`, and `webview: {directory, version, entrypoint}`. The latter entry is exactly `<directory>/msedgewebview2.exe`. The baseline helper uses role `host-probe`, lives beside the app, and requires declared/hashed app-local `vcruntime140.dll` plus any other audited helper imports in `hostProbeLibraries` before it may execute. Model metadata declares a stable `identity`, nonempty `modelFiles` list and `activation: {kind: "file", source, filename, modelId}`. The pilot supports one self-contained GGUF/bin file; grouped/multifile activation requires a future explicit contract. A model's tokenizer/config/support files must also be explicitly listed, with role `model-support`. Runtime support files use `runtime`, audited linked DLLs `native`, embedded/external app assets `resource`, source receipts `provenance`, and attribution `notice`.

CPU declarations support generic `x86-64` and a conservative `avx2-bmi2` launch gate. **No current notype binary is certified for a generic x86-64 baseline.** The small standalone Rust probe reports actual CPU/OS-state capabilities before any ORT/app import, but capability observation does not prove a binary's smallest required instruction set. ORT and all linked/dynamically loaded code still need input audit/testing. Do not mark a release assembled merely because its PE machine is x64. Unknown baselines refuse. Existing conservative C++ dispatch modules alone do not prove ORT's minimum.

The facade's pinned manifest hash anchors the expected inventory; the registry/tarball integrity and reviewed assembly inputs anchor the facade. This is corruption/packaging validation, not a signature system protecting against an attacker who rewrites every installed file and the facade. Avoid concurrent npm replacement during execution; real lock/update behavior remains a native acceptance gate.

## Pre-spawn and data contract

`inspectRelease({facadeRoot, platform, arch, env})` verifies pinned package metadata, all files and exact inventory, then returns a read-only launch plan. It performs no mkdir, history migration, model copy, app launch or network request. `prepareLaunch({...options, host})` additionally requires medium integrity/declared CPU capabilities; production supplies the already-verified baseline native probe. The CLI `--check` calls inspection only and clearly disclaims host/application acceptance.

Checks reject unsupported platform/architecture, missing packages/files, size/hash mismatch, replaced manifest, links/nonregular files, duplicate Windows-case paths, traversal/ADS/reserved paths, missing declared notices, unknown CPU baseline, install scripts, unlisted files, and recognizable private database/settings/log artifacts even if mistakenly declared. DirectML build symlinks must be dereferenced into regular bytes during **audited assembly**, never followed as installed payload links. The complete Microsoft tree contains a legitimate x86 helper inside an x64 distribution; do not trim based on every inner PE machine.

Default data is Windows RoamingAppData plus `io.github.swchen44.notype`, matching Tauri 2.11.5 `app_data_dir()`. Inspection uses APPDATA as a preview; production obtains the actual Known Folder from the native probe. An explicit absolute local `NOTYPE_DATA_DIR` is retained. **The launcher leaves this variable absent for the default root**, preserving existing native/global HF cache behavior and selections; forcing the same default root through the override would silently change HF*HOME. Relative/UNC/package-contained data paths are refused; existing ancestors are resolved before containment checks. The plan supplies exact per-process `WEBVIEW2_BROWSER_EXECUTABLE_FOLDER` and external `WEBVIEW2_USER_DATA_FOLDER=<data>/webview`, matching existing main/overlay builders. Inherited `WEBVIEW2*\*`and`GGML_BACKEND_PATH` overrides are removed; the pinned ggml loader otherwise honors the latter even after an explicit artifact-directory scan. No user/system environment or registry policy is changed.

Existing sessions.db, settings_store.json, text_processing_store.json and other user files stay in the data root. Normal launcher startup does not activate, copy, delete or download weights. The App opens its independently persisted selected model folder; onboarding/Settings can select an existing folder after the user moves the entire model root. Imported files and legacy HF cache entries remain read-only. The former explicit activation helper and its fixtures remain historical utilities; `runApplication` does not call them. Actual Windows file sharing, native discovery/load and package delivery still require separate native acceptance.

The host adapter runs the verified `notype-platform-check.exe` without a shell, with bounded output/deadline/hidden helper window. Its Rust/std and Windows system APIs inspect its own inherited token: exact medium integrity SID 8192, no elevation/UIAccess. It also reports AVX2/BMI2 and the actual RoamingAppData known folder. No ORT/ggml/WebView is imported. Probe output, arbitrary errors and environment values are never printed by the launcher. The native release entry point independently validates the complete regular-byte application/runtime manifest and its own token before Tauri/data/tray setup, sets the same fixed runtime/UDF and refuses directly invoked incomplete packages instead of starting a runtime-less host. This glue still needs the real release build/acceptance. No silent de-elevation, bootstrapper, native build, installer, postinstall or launch-time artifact download exists.
