# Portable package contracts and assembly plan

This is the first, Node-only #14 slice. All three package roles remain **private and unassembled**. The CLI can inspect verified fixture/staged packages, but deliberately refuses application launch until final native/model activation is integrated. Do not publish these placeholders or treat a small facade tarball as the complete local app.

## Roles and trust

`notype/` is the small facade. `notype-win32-x64/` is an application-specific Windows payload containing notype and the **whole** fixed Microsoft runtime, not a standalone runtime offering. `notype-model/` represents an independently pinned functional speech-model dependency. Names are provisional; no publisher scope/name reservation is implied. The root private Node package remains a diagnostic prototype and is not packed into the product.

Final facade `release.json` schema 1 must have `status: "assembled"`, a version matching its package.json, and `application`/`model` pins: `{name, version, manifest: "payload.json", sha256}`. Pin exact versions; do not use tags/ranges. Assembly must write matching exact package dependencies into the facade (Windows payload can be optional for platform selection; absence is still a clear launch error). These dependencies are absent from the unassembled source placeholder because neither release nor model has been selected.

Each payload.json declares schema/name/version/role, a nonempty exact file list, and provenance sources. Each file has `{path, role, bytes, sha256, source}`; paths use `/`. `sources[source]` contains a public HTTPS `source` URL without credentials/query/fragment, immutable `revision`, actual `license` identification and `notices` paths. Every notice must itself be a declared, hashed notice file. Preserve proprietary component terms; an observed artifact SHA is not a publisher-provided digest or a redistribution grant.

Application metadata declares `platform: "win32"`, `arch: "x64"`, `cpu: "x86-64"`, `entrypoint`, and `webview: {directory, version, entrypoint}`. The latter entry is exactly `<directory>/msedgewebview2.exe`. Model metadata declares a stable `identity` and nonempty `modelFiles` list. A model's tokenizer/config/support files must also be explicitly listed, with role `model-support`. Runtime support files use `runtime`, audited linked DLLs `native`, embedded/external app assets `resource`, source receipts `provenance`, and attribution `notice`.

The foundation only understands a generic x86-64 CPU declaration. **No current notype binary is certified for that baseline.** ORT and all linked/dynamically loaded code still need minimum-instruction audit/testing. Do not mark a release assembled using that declaration merely because its PE machine is x64. If selected binaries require AVX2/BMI2, add a tested pre-spawn capability adapter/contract and explicit higher baseline; unsupported/unknown baseline currently refuses. Existing conservative C++ dispatch modules alone do not prove ORT's minimum.

The facade's pinned manifest hash anchors the expected inventory; the registry/tarball integrity and reviewed assembly inputs anchor the facade. This is corruption/packaging validation, not a signature system protecting against an attacker who rewrites every installed file and the facade. Avoid concurrent npm replacement during execution; real lock/update behavior remains a native acceptance gate.

## Pre-spawn and data contract

`inspectRelease({facadeRoot, platform, arch, env})` verifies pinned package metadata, all files and exact inventory, then returns a read-only launch plan. It performs no mkdir, history migration, model copy, app launch or network request. `prepareLaunch({...options, host})` additionally requires medium integrity; production supplies a bounded inherited-token probe. The CLI `--check` calls inspection only and clearly disclaims host/application acceptance.

Checks reject unsupported platform/architecture, missing packages/files, size/hash mismatch, replaced manifest, links/nonregular files, duplicate Windows-case paths, traversal/ADS/reserved paths, missing declared notices, unknown CPU baseline, install scripts, unlisted files, and recognizable private database/settings/log artifacts even if mistakenly declared. DirectML build symlinks must be dereferenced into regular bytes during **audited assembly**, never followed as installed payload links. The complete Microsoft tree contains a legitimate x86 helper inside an x64 distribution; do not trim based on every inner PE machine.

Default data is `%APPDATA%/io.github.swchen44.notype`, matching Tauri 2.11.5 Windows `app_data_dir()` (RoamingAppData plus the existing identifier). An explicit absolute local `NOTYPE_DATA_DIR` is retained. Relative/UNC/package-contained data paths are refused; existing ancestors are resolved before containment checks. The plan supplies exact per-process `NOTYPE_DATA_DIR`, `WEBVIEW2_BROWSER_EXECUTABLE_FOLDER` and external `WEBVIEW2_USER_DATA_FOLDER=<data>/webview2`; inherited `WEBVIEW2_*` overrides are removed. It never changes user/system environment or registry policy.

Existing sessions.db, settings_store.json, text_processing_store.json, models and other user files remain at the same root. Model files will be verified locally and atomically activated from installed dependencies into the existing `<data>/models` layout; no runtime fetch. **That copy/catalog-selection integration is still pending**, so the current CLI deliberately returns `launch-not-integrated` after successful checks. No microphone/provider outputs or native application launches are simulated.

The host adapter runs the Windows system `whoami.exe /groups /fo csv /nh` without a shell, with bounded output/deadline/hidden helper window. Inherited token integrity SID 8192 is required; high/system/low/UIAccess/unknown levels refuse. Its output and arbitrary exceptions/environment are never printed. This normal-user requirement avoids the documented elevated-host WebView environment override limitation. No silent de-elevation, bootstrapper, native build, installer, postinstall or launch-time artifact download exists.

## Bounded final assembly after dependencies release

1. Wait for #13 merge/runtime receipt and #12 final model/normalizer proof. Obtain the shared native-target lease; refresh actual disk figures. No build/cache deletion or large copy belongs to this first slice.
2. Preserve the final native app and audited linked/dynamically loaded DLL/resource inputs as regular bytes. Preserve the approximately 12 MiB transcribe-cpp **install subset** independently before retiring any derived target: the apparent C cache is a junction into D native output. Follow the reviewed storage receipt; do not clean through it. The #13 owner now owns the small `rlib`-only manifest adjustment.
3. Choose/test explicit release profile and CPU baseline. Record build/lock/toolchain/source commits and actual regular-byte file hashes/imports. The current debug snapshot is preparation evidence only.
4. Assemble a fresh small-metadata plan before copying: exact source/destination/file role/size/hash/source revision/notice mapping, expected file count/size and per-volume peak budget. Entry points are x64; full vendor runtime support tree is retained. Stop if any source changes or a disk floor would be breached. No blind Cargo-directory glob or inherited developer-cache symlink.
5. Reuse the already verified fixed runtime 156.0.4314.42 inputs in the external prep cache. Preserve all 257 vendor files and applicable EULA/notices; do not run vendor BAT/scripts or trim disputed license components. Keep license/public-redistribution questions distinct from private local execution.
6. Select a quality-accepted, licensed model; include every required tokenizer/config/weight file, immutable source revision and per-file hashes. Add tested local atomic activation and the actual native catalog selection without deleting old user models. Preserve primary model/history state across interrupted copies and retries.
7. Generate full manifests and exact facade dependency pins. Pack with `npm pack --ignore-scripts --offline --json`; inspect the **actual extracted tarball**, exact inventory/hashes/notices and private-data exclusions. Source-tree checks or an npm dry-run alone do not establish final artifact contents. Measure compressed/unpacked/publish-body/update peak separately.
8. Wire the verified native launch only after the model/data integration exists. Use an absolute app path, shell=false, fixed runtime/UDF, normal-user token, bounded actionable diagnostics and no arbitrary arguments/environment logging. Coordinate an owned normal-user launch slot and fresh test data; observe actual fixed runtime module images and offline behavior, real model inference, target guard and SQLite restart.
9. Test two actual package versions, interruptions, locked files and side-by-side running runtime versions against the **same** data root. Current byte-sentinel tests only prove plan resolution/nonmutation; they are not native migrations or update-lock acceptance.

No company API/Proxy or public registry access is required for the local artifact work. Their actual results, publisher permissions and redistribution acceptance remain unperformed; do not substitute fixtures or request keys to complete this slice.
